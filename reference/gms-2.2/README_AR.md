# GMS 2.2 — حزمة تثبيت قاعدة البيانات ومحرك الحسابات والاختبارات

**الحالة: مسودة هندسية قابلة للمراجعة، وليست جاهزة للإنتاج.**

هذه حزمة تطوير جديدة مشتقة من SRS 2.1 وSQL 2.1؛ لا تُطبق مباشرة على قاعدة تشغيلية أو قاعدة تحتوي بيانات حقيقية. لا يوجد مسار Migration من 2.1 في هذه الحزمة.

## تصميم الحركة المالية الدقيقة

دفتر `ledger_entries` يحتفظ بالقيم الدقيقة لا بالمبالغ المدوّرة؛ فمثلًا تسجل تكلفة 21.45 كحركة +21.45، وبعد دفع 21 تصبح الحركة الإجمالية 0.45. إذا كانت تكلفة القراءة التالية 15.80 تصبح ذمة المشترك 16.25؛ المطلوب 16 والكسر 0.25. كلاهما مشتق من رصيد واحد، فلا يُضاف الكسر يدويًا مرة ثانية.

كل دفعة أو تسوية أو عكس دفعة حركة مستقلة مع مفتاح/مصدر، ويعاد حساب الرصيد من مجموعها. لا يُعدل كشف مغلق؛ التصحيح اللاحق يُسجّل كتسوية. الكشوف النهائية تُنشأ داخل `gms_finalize_cycle` وتستوعب أكثر من قراءة لنفس المشترك في الدورة.

## تشغيل الاختبارات باستخدام PostgreSQL 16 أو أحدث

للاستخدام داخل **بيئة اختبار جديدة وفارغة فقط**، جهّز PostgreSQL 16+ وعميل `psql` وتأكد أن لديك حساب اختبار يملك صلاحية إنشاء الجداول والدوال. ثم داخل مجلد الحزمة:

```bash
export GMS_TEST_DATABASE_URL='postgresql://TEST_USER:TEST_PASSWORD@localhost:5432/gms_test'
bash tests/run_postgres.sh
```

يقوم السكربت بإنشاء الجداول والوظائف ثم تنفيذ محاولات إفساد مقصودة، ويوقف العمل عند أي فشل. تجرى الاختبارات داخل معاملة تنتهي بـ `ROLLBACK`، لكن **الجداول التجريبية تظل موجودة** لأن تثبيتها يتم في ملفات سابقة. لذلك لا تشغله أبدًا على قاعدة موجودة.

لتشغيل الاختبارات المحلية التي لا تحتاج خادم PostgreSQL:

```bash
python -m unittest discover -s tests -p 'test_*.py' -v
```

## حدود الأمان المهمة

- `gms.actor_id` سياق يمرره **خادم API موثوق بعد مصادقة مستخدم حقيقية** في معاملة. ليس من الآمن منح مستخدم Android اتصال PostgreSQL مباشرًا أو القدرة على اختيار `actor_id`.
- تُسحب الصلاحيات العامة على الجداول والدوال؛ يجب على مسؤول قاعدة البيانات إنشاء حساب خدمة محدود ومنحه `EXECUTE` على الدوال اللازمة فقط، مع رفض DML المباشر. لم تُنشأ حسابات الإنتاج في هذا التصميم.
- الـ `SECURITY DEFINER` وظائف تجريبية تحتاج مراجعة تفويض مستقلة قبل النشر. مستخدم DB بصلاحيات مالك/مشرف فائق يستطيع تجاوز بعض الحواجز.
- تسجيل صورة بحالة `ready` في قاعدة البيانات لا يثبت أن ملفها موجود وسليم؛ يتحقق API من الـ Object Storage والبصمة والوصول قبل تمرير الطلب.
- `Asia/Gaza` منطقة زمنية افتراضية في دوال ربط القراءة بالدورة، ويجب تأكيدها مع العميل قبل التشغيل.
- استيراد Excel، رفع الصور وتخزينها، PIN وبيانات Android المحلية، اعتماد جماعي كامل، إعادة تسلسل قراءة قديمة، تغيير عداد داخل دورة ذات أكثر من تركيب، خدمات النسخ الفعلي وواجهات Web/Android كلها أعمال إضافية لم تكتمل بهذه الحزمة.
- عمليات المالية القديمة لا تُهاجر تلقائيًا؛ يجب بناء خطة مطابقة وحفظ وتراجع مع بيانات العميل الحقيقية قبل أي تحديث إنتاجي.

## شروط إنهاء المشروع

1. اجتياز جميع اختبارات PostgreSQL الفعلية وتوثيقها.
2. مراجعة أمن صلاحيات الاتصال والخدمات واختبار API كموظف ومدير.
3. مطابقة الأرصدة بدقة مع مرجع `Decimal` مستقل، بما فيها الدفعات الجزئية والعكس والتزامن.
4. بناء وتحقق تطبيق Android وواجهة Web وصور التخزين والنسخ والاستعادة.
5. موافقة العميل على SRS والمراحل والتكلفة والعقد.
